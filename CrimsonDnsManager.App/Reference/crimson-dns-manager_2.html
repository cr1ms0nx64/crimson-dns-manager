⚠ Developer Notice · Implementierungshinweise für DNS Manager ▾
Daten & API
Cloudflare REST API
  • Basis-URL: https://api.cloudflare.com/client/v4
  • Auth-Header: Authorization: Bearer {token}
  • DNS Records laden: GET /zones/{id}/dns_records?per_page=100
  • Record erstellen: POST /zones/{id}/dns_records
  • Record löschen: DELETE /zones/{id}/dns_records/{record_id}
  • Zone-ID per Name: GET /zones?name=cr1ms0n.xyz
  • API Token nie im Frontend plain speichern — httpOnly Cookie oder Backend-Proxy bevorzugen.
Tabelle & Filter
DNS Records Tabelle
  • Tabelle ist clientseitig filterbar — Daten einmal laden, dann filtern ohne API-Call.
  • Suchfeld filtert über Name, Typ und Content gleichzeitig (case-insensitive).
  • Typ-Filter-Chips exklusiv (nur ein Typ gleichzeitig aktiv, oder "Alle").
  • Content-Zelle: langer Text per text-overflow: ellipsis, Tooltip bei Hover mit Full-Content.
  • Proxy-Toggle: Cloudflare proxied: true/false — direkt per PATCH Record aktualisieren.
  • Selektion: Checkbox pro Zeile + Checkbox im Header für "Alle markieren / alle abwählen".
  • Selektierte Zeilen bekommen roten Hintergrund-Tint + linken Border als visuellen Marker.
  • Selection-Bar erscheint animiert sobald ≥1 Record markiert ist, zeigt Anzahl + "Auswahl aufheben".
  • "Auswahl löschen"-Button in Topbar erscheint nur wenn ≥1 markiert (dynamisch per JS, display:none/flex).
  • Delete öffnet Modal mit Liste aller markierten Records — kein window.confirm().
  • Record-Typen mit eigener Farbe: A=Cyan, AAAA=Hellcyan, CNAME=Amber, MX=Lila, TXT=Grün, SRV=Orange.
Backup & Speichern
Backup-Logik & Toast-Farben
  • Backup vor Speichern: aktuellen Zustand als JSON dumpen, lokal ablegen.
  • Backup-Format: cr1ms0n.xyz_backup_YYYYMMDD_HHMMSS.json
  • Backup enthält: alle Records mit ID, type, name, content, ttl, proxied.
  • Backup-Ordner öffnen: Electron shell.openPath() oder Tauri fs API.
  • "DNS speichern" zeigt grünen Toast bei Erfolg — CSS-Klasse .toast.green.
  • Fehler beim Speichern → roter Toast (.toast.red). Standard-Info bleibt cyan.
  • "DNS speichern" Button: nur aktiv wenn Änderungen vorliegen (dirty state tracken).
  • Bulk-Änderungen batchen — nicht jede Änderung sofort zur API senden.
UI-Zustände
Loading / Error / Empty
  • Tabelle zeigt Skeleton-Rows beim Laden (gleiche Höhe, kein Layout-Shift).
  • Leerer State: Illustration + CTA "DNS Records laden" wenn noch keine Records geladen.
  • Error State: Toast + Retry-Button wenn API-Call scheitert.
  • Livefeed zeigt alle API-Calls mit Timestamp, HTTP-Methode und Status.
  • Livefeed auto-scrollt nach unten bei neuem Eintrag.
  • Toast-Queue: max. 3 gleichzeitig, älteste zuerst entfernen, Timeout 3.5s.
App Shell
Electron / Tauri Hinweise
  • Desktop-App — kein Browser-Target nötig, aber CORS via Backend-Proxy trotzdem empfohlen.
  • API Token im Electron-Store (electron-store) oder Keychain verschlüsselt ablegen.
  • Update-Flow: Paket wählen → prüfen (Hash/Signatur) → installieren → neu starten.
  • Schnellaktionen "next A Record" / "acp A Record" befüllen das Formular vor — nicht direkt pushen.
  • Topbar: Sticky, immer sichtbar. Actions-Buttons oben rechts — höchste Interaktionsfrequenz.
  • Sidebar: Scrollbar sichtbar halten; Sections collapsible wenn zu lang.
Record-Formular Pflichtfelder nach Typ
Record hinzufügen / bearbeiten — Validierungsregeln
// Pflichtfelder je Record-Typ const required = { 'A': ['name', 'content'], // content = IPv4 'AAAA': ['name', 'content'], // content = IPv6 'CNAME': ['name', 'content'], // content = Zieldomain 'MX': ['name', 'content', 'priority'], // priority: 0–65535 'TXT': ['name', 'content'], // content = beliebiger String 'SRV': ['name', 'content', 'priority', 'data.weight', 'data.port'], }; // TTL: 1 = Auto (Cloudflare), oder Sekunden (min 60) // proxied: nur für A, AAAA, CNAME möglich — für MX/TXT/SRV immer false // name '@' = Zone-Apex, wird von CF zu cr1ms0n.xyz expandiert
